# Play to Grow

**Основной слоган: «Играй, чтобы расти» / “Play to Grow”.**

Публичная посадочная страница набирает семьи для пилотной работы с компьютерной и игровой зависимостью и приглашает психологов к сотрудничеству. Отдельная демоверсия показывает механику: ребенок выбирает полезные задания, родитель проверяет результат и выдает согласованные награды, модератор формирует план развития. **playtogrow.ru** и **playtogrow.online** публикуют одинаковую русскоязычную версию из одного набора исходников; на обоих доменах доступно переключение на английский язык.

На странице открыто указано, что родительское финансирование пилота направляется только на разработку, инфраструктуру и развитие методики; автор не получает личной прибыли до ввода платформы в эксплуатацию. Публичные контакты задаются в `docs/contact-config.js`.

## Быстро посмотреть

Откройте `release/Play to Grow — RU.html` или `release/Play to Grow — EN.html` двойным щелчком — это автономные посадочные страницы. Кнопка демо ведет на соседний файл `Play to Grow — RU Demo.html` или `Play to Grow — EN Demo.html`. Все четыре файла создаются командой `python scripts/package_site.py` и работают без установки и сервера.

Для разработки запустите `start-preview.cmd` или выполните из этой папки:

```powershell
python -m http.server 4173 --bind 127.0.0.1 --directory docs
```

Откройте http://127.0.0.1:4173. Посадочная страница находится в `index.html`, интерактивный прототип — в `demo.html`. Остановка сервера — Ctrl+C. Если порт уже занят этим предпросмотром, откройте существующий адрес.

## Как пройти сценарий

1. В роли **Ребенок** откройте «Еще одна глава», напишите отчет и отправьте на проверку.
2. Выберите **Родитель** в верхнем меню. В разделе «Проверка заданий» подтвердите отчет либо верните с пояснением. За подтверждение добавятся 30 баллов.
3. В роли ребенка откройте «Мои награды», выберите 30 минут игры за 60 баллов и отправьте заявку. Баллы резервируются.
4. Родитель открывает «Награды» и отмечает фактическую выдачу. При отмене ожидающей заявки баллы возвращаются.
5. В роли **Модератор** измените цель развития или добавьте задание из библиотеки. Оно появится у ребенка.

Начальное состояние: восемь заданий, три из них выполнены, одно в работе, одно на проверке; 150 баллов заработано на трех выполненных заданиях. Примерные лимиты — 60 минут игры в день и 500 ₽ в неделю; их выбирает семья, это не возрастные рекомендации.

## Что работает

- Три кабинета и шесть направлений: учеба, чтение, движение, творчество, общение, самостоятельность.
- Русский и английский интерфейс, двуязычные исходные задания, награды и библиотека; язык сохраняется в браузере.
- Раздел «Как это работает» с принципом «выбор, а не торговля», ролями участников, циклом задания и честными ограничениями демоверсии.
- Создание и выбор задания, текстовый отчет, подтверждение или доработка с комментарием.
- Раздельный учет накопленного опыта и доступных баллов; защита от повторной проверки.
- Заявка на игровое время, бонус, валюту или совместное занятие; выдача родителем и отмена с возвратом.
- Дневной лимит времени и недельный бюджет, включая ожидающие заявки. Даты считаются по Москве; неделя с понедельника.
- Изменение игры, псевдонима и семейных договоренностей; цель и фокус развития у модератора.
- Прогресс, достижения, сохранение в `localStorage`, экспорт и проверяемый импорт JSON, сброс демо.
- Адаптивная верстка, клавиатурная навигация, диалоговые окна, поддержка уменьшения анимации.

**Это демонстрация на одном устройстве.** Переключатель ролей не является авторизацией. Данные можно изменить средствами браузера. Реальные личные сведения ребенка здесь не нужны. Сайт не измеряет экранное время, не блокирует игры, не покупает и не начисляет валюту внутри игр. Родитель предоставляет согласованную награду самостоятельно. Продукт не заявляет лечебной или диагностической эффективности.

Браузеры и разные адреса сайта имеют отдельные хранилища. При переходе с localhost на GitHub Pages или собственный домен перенесите данные через «Как попробовать → Скачать копию → Восстановить из файла». Очистка данных браузера удалит локальное демо. На некоторых устройствах браузер может запрещать сохранение для локальных HTML-файлов; тогда используйте HTTP-предпросмотр.

## Два репозитория GitHub Pages

Скрипт создает два готовых архива:

| Версия | Архив | Репозиторий | Домен |
| --- | --- | --- | --- |
| Русская | `release/playtogrow-ru-github-pages.zip` | `playtogrow-ru` | `playtogrow.ru` |
| Online (русский по умолчанию) | `release/playtogrow-en-github-pages.zip` | `playtogrow-online` | `playtogrow.online` |

Для каждого репозитория:

1. Создайте публичный репозиторий с указанным именем.
2. Распакуйте соответствующий архив и загрузите его содержимое в корень репозитория.
3. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
4. В **Actions → Publish Play to Grow → Run workflow** запустите публикацию.
5. В **Settings → Pages → Custom domain** укажите домен нужной версии.
6. После проверки DNS включите **Enforce HTTPS**.

Оба архива содержат одинаковую проверенную логику, но разные `lang`, метаданные и язык по умолчанию. На реальных доменах кнопки RU/EN переводят между `playtogrow.ru` и `playtogrow.online`, сохраняя выбранную роль и экран через hash-навигацию. На временных адресах `github.io` язык переключается локально.

Workflow запускает тесты и проверку синтаксиса, затем публикует только `docs/`. Сборщик и npm-установка не нужны.

### DNS для каждого домена

Сначала подтвердите владение доменами в GitHub Settings → Pages с предложенными GitHub TXT-записями. Для корня `@` обоих доменов используйте A-записи GitHub Pages:

```text
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

Для `www` задайте CNAME на `<login>.github.io` без имени репозитория. Выпуск сертификата и обновление DNS могут занять время.

При публикации через Actions-workflow файл `CNAME` не требуется: домен задается в настройках Pages каждого репозитория.

## Ограничения GitHub Pages

GitHub Pages размещает статические HTML/CSS/JS; Express, Python-бот и PostgreSQL из старого прототипа там не запускаются. У сайта нет серверных секретов, внешних библиотек, аналитики и запросов к игровым API.

По проверенной документации: опубликованный сайт до 1 ГБ; мягкий лимит трафика 100 ГБ в месяц; развертывание до 10 минут. Мягкое ограничение 10 сборок в час не распространяется на пользовательский Actions-workflow. Ограничения коммерческого SaaS и чувствительных транзакций остаются применимыми.

Для реального многопользовательского продукта нужен отдельный сервис авторизации и приватная база: проверка членства в семье и роли на сервере, атомарное начисление/списание баллов, хранение и удаление данных. Текущая демонстрация такой защиты не обещает.

## Исходники и проверки

```text
docs/index.html       двуязычная посадочная страница
docs/landing.css      адаптивное оформление посадочной страницы
docs/landing.js       переключение языка и контактные ссылки
docs/contact-config.js  публичные контакты автора
docs/demo.html        оболочка интерактивной демоверсии
docs/styles.css       адаптивное оформление демоверсии
docs/app.js           кабинеты, переводы, диалоги, хранилище, импорт/экспорт
docs/model.js         состояния заданий, баллы, награды, лимиты и валидация
docs/assets/mark.svg  логотип
tests/model.test.mjs  проверки бизнес-логики
scripts/package_site.py  два архива и четыре автономные HTML-версии
.github/workflows/pages.yml  публикация только статического сайта
```

```powershell
node --test tests/model.test.mjs
node --check docs/app.js
node --check docs/model.js
node --check docs/contact-config.js
node --check docs/landing.js
python scripts/package_site.py
```

Для проверки нужен Node.js 20+ и Python 3.10+ только для упаковки. Самому сайту нужен современный браузер. Старые приложения в `artifacts/` сохранены; их сборка для этой версии не требуется.
