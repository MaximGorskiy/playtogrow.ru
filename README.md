# Play to Grow

**Основной слоган: «Играй, чтобы расти» / “Play to Grow”.**

Публичная посадочная страница набирает семьи для пилотной работы с компьютерной и игровой зависимостью и приглашает психологов к сотрудничеству. Отдельная демоверсия показывает механику: ребенок выбирает полезные задания и отмечает игровые достижения, родитель проверяет результаты и выдает согласованные награды, модератор формирует реальный и игровой планы развития. **playtogrow.ru** и **playtogrow.online** публикуют один двуязычный набор страниц. Русские страницы каноничны на `.ru`, английские — на `.online/en/`; переключатель RU/EN ведет на статический URL выбранного языка.

На странице открыто указано, что родительское финансирование пилота направляется только на разработку, инфраструктуру и развитие методики; автор не получает личной прибыли до ввода платформы в эксплуатацию. Публичные контакты задаются в `docs/contact-config.js`.

## Быстро посмотреть

Откройте `release/Play to Grow — RU.html` или `release/Play to Grow — EN.html` двойным щелчком — это автономные посадочные страницы. Кнопка демо ведет на соседний файл `Play to Grow — RU Demo.html` или `Play to Grow — EN Demo.html`. Все четыре файла создаются командой `python scripts/package_site.py` и работают без установки и сервера.

Для разработки запустите `start-preview.cmd` или выполните из этой папки:

```powershell
python -m http.server 4173 --bind 127.0.0.1 --directory docs
```

Откройте http://127.0.0.1:4173. Посадочная страница находится в `index.html`, интерактивный прототип — в `demo.html`. Остановка сервера — Ctrl+C. Если порт уже занят этим предпросмотром, откройте существующий адрес.

## Как пройти сценарий

1. В роли **Ребенок** откройте «Еще одна глава», напишите отчет и отправьте на проверку.
2. Выберите **Родитель** в верхнем меню. В разделе «Проверка заданий» подтвердите отчет либо верните с пояснением. За подтверждение добавятся 30 баллов.
3. В роли ребенка откройте «Мой прогресс», отметьте игровое достижение и фактически проведенное в игре время.
4. Родитель в разделе «Прогресс» подтверждает достижение. За него начисляются баллы; сами минуты баллов не приносят.
5. В роли ребенка откройте «Мои награды», выберите игровой бонус за 60 баллов и отправьте заявку. Баллы резервируются. Родитель отмечает фактическую выдачу; при отмене ожидающей заявки баллы возвращаются.
6. В роли **Модератор** откройте «Прогресс» и измените видимый ребенку игровой план, баллы за достижение и список смежных игр или легких этапов. Здесь же можно изменить цель развития или добавить реальное задание из библиотеки.

Начальное состояние: восемь реальных заданий, три из них выполнены, одно в работе, одно на проверке; 150 баллов заработано на трех выполненных заданиях. Также есть один игровой результат на проверке, недельный план из трех игровых этапов и примерный бюджет наград 500 ₽ в неделю. Жесткого лимита игрового времени нет: ребенок вводит минуты вручную для последующего обсуждения с психологом.

## Что работает

- Три кабинета и шесть направлений: учеба, чтение, движение, творчество, общение, самостоятельность.
- Русский и английский интерфейс, отдельные индексируемые URL обоих языков, двуязычные исходные задания, награды и библиотека.
- Раздел «Как это работает» с принципом «выбор, а не торговля», ролями участников, двумя циклами прогресса и честными ограничениями демоверсии.
- Создание и выбор задания, текстовый отчет, подтверждение или доработка с комментарием.
- Видимый недельный план игрового прогресса, ручная запись достижений и времени, подтверждение результата и защита от повторного начисления.
- Раздельный учет накопленного реального опыта и доступных баллов; игровые достижения также увеличивают доступный баланс.
- Заявка на игровой бонус, валюту или совместное занятие; выдача родителем и отмена с возвратом.
- Недельный бюджет наград, включая ожидающие заявки. Неделя считается с понедельника по московскому времени.
- Изменение игры, псевдонима и семейных договоренностей; цель, фокус развития, игровой план и варианты смежных игр у модератора.
- Если игровой план не выполнен, ребенку предлагается добровольный дополнительный реальный квест без потери баллов и скрытых штрафов.
- Общий прогресс, достижения, сохранение в `localStorage`, экспорт и проверяемый импорт JSON, сброс демо.
- Адаптивная верстка, клавиатурная навигация, диалоговые окна, поддержка уменьшения анимации.

**Это демонстрация на одном устройстве.** Переключатель ролей не является авторизацией. Данные можно изменить средствами браузера. Реальные личные сведения ребенка здесь не нужны. Сайт не подключается к игре и не измеряет время автоматически: достижения и минуты вводятся вручную. Он не блокирует игры, не покупает и не начисляет валюту внутри игр. Родитель предоставляет согласованную награду самостоятельно. Продукт не заявляет лечебной или диагностической эффективности.

Браузеры и разные адреса сайта имеют отдельные хранилища. При переходе с localhost на GitHub Pages или собственный домен перенесите данные через «Как попробовать → Скачать копию → Восстановить из файла». Очистка данных браузера удалит локальное демо. На некоторых устройствах браузер может запрещать сохранение для локальных HTML-файлов; тогда используйте HTTP-предпросмотр.

## Два репозитория GitHub Pages

Скрипт создает два готовых архива:

| Версия | Архив | Репозиторий | Домен |
| --- | --- | --- | --- |
| Русская | `release/playtogrow-ru-github-pages.zip` | `playtogrow-ru` | `playtogrow.ru` |
| Online с канонической английской веткой `/en/` | `release/playtogrow-en-github-pages.zip` | `playtogrow-online` | `playtogrow.online` |

Для каждого репозитория:

1. Создайте публичный репозиторий с указанным именем.
2. Распакуйте соответствующий архив и загрузите его содержимое в корень репозитория.
3. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
4. В **Actions → Publish Play to Grow → Run workflow** запустите публикацию.
5. В **Settings → Pages → Custom domain** укажите домен нужной версии.
6. После проверки DNS включите **Enforce HTTPS**.

Оба архива содержат одинаковые публичные страницы и демо. Отличаются только доменные `robots.txt` и `sitemap.xml`: карта `.ru` содержит русские канонические URL, карта `.online` — английские URL `/en/`. На реальных доменах кнопки RU/EN переводят между каноническими языковыми адресами. В демо выбранный язык передается параметром `lang`, а роль и экран сохраняются через hash-навигацию.

## Поиск, агенты и LLM

- В корне публикуются `robots.txt`, доменный `sitemap.xml`, `llms.txt`, `llms-full.txt`, RSS и публичный файл ключа IndexNow.
- Поисковое чтение разрешено для `OAI-SearchBot`, `Claude-SearchBot`, `PerplexityBot` и пользовательских загрузчиков. `GPTBot`, `ClaudeBot` и `Google-Extended` запрещены до отдельного решения владельца об использовании материалов для разработки моделей.
- Русские страницы каноничны на `https://playtogrow.ru/`, английские — на `https://playtogrow.online/en/`. Каждая пара связана `hreflang`; важный текст присутствует в исходном HTML.
- Страницы содержат уникальные title/description, Open Graph, JSON-LD, дату обновления, внутренние ссылки и видимые ограничения проекта.
- `demo.html` имеет `noindex,follow` и не входит в sitemap; закрытый backend и CRM в публикацию не входят.
- После успешного GitHub Pages deploy workflow отправляет канонические URL в IndexNow. Ошибка внешнего сервиса не отменяет успешную публикацию.
- `scripts/build_discovery.py` создает и проверяет английскую посадочную, 11 пар информационных страниц и служебные файлы. Новый или измененный русский блок с `data-i18n` без английского перевода останавливает сборку.

Workflow запускает тесты и проверку синтаксиса, затем публикует только `docs/`. Сборщик и npm-установка не нужны.

### DNS для каждого домена

Сначала подтвердите владение доменами в GitHub Settings → Pages с предложенными GitHub TXT-записями. Для корня `@` обоих доменов используйте A-записи GitHub Pages:

```text
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

Для `www` задайте CNAME на `<login>.github.io` без имени репозитория. Выпуск сертификата и обновление DNS могут занять время.

При публикации через Actions-workflow файл `CNAME` не требуется: домен задается в настройках Pages каждого репозитория.

## Ограничения GitHub Pages

GitHub Pages размещает статические HTML/CSS/JS; Express, Python-бот и PostgreSQL из старого прототипа там не запускаются. У сайта нет серверных секретов, внешних библиотек, аналитики и запросов к игровым API.

По проверенной документации: опубликованный сайт до 1 ГБ; мягкий лимит трафика 100 ГБ в месяц; развертывание до 10 минут. Мягкое ограничение 10 сборок в час не распространяется на пользовательский Actions-workflow. Ограничения коммерческого SaaS и чувствительных транзакций остаются применимыми.

Для реального многопользовательского продукта нужен отдельный сервис авторизации и приватная база: проверка членства в семье и роли на сервере, атомарное начисление/списание баллов, хранение и удаление данных. Текущая демонстрация такой защиты не обещает.

```powershell
python scripts/build_discovery.py --check
node --test tests/model.test.mjs tests/site.test.mjs
node --check docs/app.js
node --check docs/model.js
node --check docs/contact-config.js
node --check docs/landing.js
python -m py_compile scripts/build_discovery.py scripts/notify_indexnow.py scripts/package_site.py
python scripts/package_site.py
```

Для проверки нужен Node.js 20+ и Python 3.10+ только для упаковки. Самому сайту нужен современный браузер. Старые приложения в `artifacts/` сохранены; их сборка для этой версии не требуется.
